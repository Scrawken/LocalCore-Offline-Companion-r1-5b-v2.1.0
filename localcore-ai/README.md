# LocalCore AI — In-House Model Program

**Status:** Scaffold (no training runs yet)
**Created:** 2026-10-30
**Goal:** Replace the seven external models in the current stack with three fine-tuned models that LocalCore owns and brands — without disrupting the production app until each in-house model beats its teacher on evaluation.

---

## The Three Projects

| Project | Codename | Capabilities | Base model | License | Training hardware |
|---|---|---|---|---|---|
| [omni/](omni/README.md) | **LocalCore-Omni** | Text chat, image understanding, speech in, speech out | Qwen2.5-Omni-3B | Apache 2.0 | RTX 3060 12GB (QLoRA) — can start now |
| [create/](create/README.md) | **LocalCore-Create** | Image generation, video generation (staged) | FLUX.1-schnell | Apache 2.0 | Needs 24GB+ GPU — queued |
| [audio/](audio/README.md) | **LocalCore-Audio** | Music and audio generation | Stable Audio Open Small | Stability Community (free < $1M revenue) | Needs 24GB+ GPU — queued |

## Strategy

1. **Teachers stay in production.** The current seven models (Dolphin 3.0 8B, Qwen2.5-VL-3B, Whisper small.en, Piper, FLUX.1-schnell, MusicGen, SVD-XT) keep running the app. Nothing in this folder affects the shipping stack.
2. **Distill, then fine-tune.** Teachers generate training data (prompt → response pairs across every capability). Students fine-tune from commercially-safe open-weight bases on that data.
3. **Data first.** ~70% of the labor is dataset construction, curation, and evaluation — all doable on the RTX 3060 today. Training runs for Create and Audio are queued until a 24GB+ GPU is available.
4. **Evals gate adoption.** A student replaces a teacher only when it passes the same smoke tests (`test:vision`, `test:speech`, `test:chat-model`) plus project-specific evals defined in each project folder.

## Licensing Rules (commercial-bound)

LocalCore will eventually be commercial. These rules are non-negotiable for anything in this folder:

- **Base models must be commercially usable.** Approved: Apache 2.0 (Qwen, FLUX.1-schnell), Stability Community < $1M revenue (Stable Audio Open Small).
- **MusicGen and FLUX.1-dev are excluded as bases** (non-commercial weight licenses). MusicGen may remain a *production* model for now but must be replaced before commercial launch.
- **Dolphin 3.0 (Llama license) outputs must NOT be used to train non-Llama models.** The Llama Community License restricts using outputs to improve models that are not Llama derivatives. Text training data for Omni must come from Apache-safe sources: self-instruct data generated by the Qwen base itself, human-written persona data, or Apache-licensed datasets. See [omni/data/README.md](omni/data/README.md).
- **Every dataset records its teacher source and license** in its manifest so provenance is auditable.

## What "Singular" Buys Us

Even an omni model generates sequentially internally (text tokens, then audio tokens). The real win is eliminating **chain-link orchestration**: one model resident in VRAM, one pipeline call, no inter-model handoff code. That is the simplification this program delivers.

## Folder Layout

```
localcore-ai/
  README.md            ← this file
  omni/                ← Model A: text + vision + speech
    README.md          ← base model, license, data recipe, hardware plan, evals
    configs/           ← training configs (reference until first run)
    data/              ← data recipes and manifests (raw data git-ignored)
  create/              ← Model B: image + video
    README.md
    configs/
    data/
  audio/               ← Model C: music/audio
    README.md
    configs/
    data/
```

Model weights, checkpoints, and raw/generated datasets are **not committed to git** (covered by `.gitignore`). They will be downloaded and pinned by SHA-256 via setup scripts, matching the existing `setup:local-model` / `setup:multimodal` pattern.
